TASKFLOW - PROJECT DOCUMENTATION
================================

PROJECT OVERVIEW
----------------
TaskFlow is a high-performance team management tool built for modern workflows.
It combines the power of Next.js 15 with Supabase's real-time capabilities to
provide a seamless, low-latency task management experience.

CORE FEATURES
-------------
1. AUTHENTICATION:
   - Google OAuth integration for one-click sign-in.
   - Email/Password authentication via Supabase Auth.
   - Automatic user profile creation on first login.

2. PROJECT MANAGEMENT:
   - Create workspaces (projects).
   - Invite team members and assign roles (Admin/Member).
   - Dedicated project dashboards.

3. REAL-TIME KANBAN:
   - Interactive board for 'To Do', 'In Progress', and 'Done'.
   - Drag-and-drop task movement.
   - Instant synchronization across all users viewing the same project.

4. TASK DETAILS:
   - Priority levels (Low, Medium, High).
   - Detailed descriptions and due dates.
   - Task assignment to specific team members.

5. AUDIT & ACTIVITY:
   - Automatic logging of every task change.
   - Activity feed showing who changed what and when.

TECHNICAL STACK
---------------
- Frontend: React 19, Next.js 16 (App Router)
- Styling: Tailwind CSS 4.0
- Backend: Supabase (Postgres, SSR, Realtime)
- Components: Radix UI, Lucide React
- Logic: Zod, React Hook Form, TanStack Query

LOCAL DEVELOPMENT SETUP
-----------------------
Follow these steps to get the project running on your local system:

1. PREREQUISITES:
   - Node.js (v18.0.0 or higher)
   - npm or yarn
   - A Supabase account (Free tier works perfectly)

2. CLONE & INSTALL:
   ```bash
   git clone https://github.com/yourusername/task-manager-fullstack.git
   cd task-manager-fullstack
   npm install
   ```

3. SUPABASE SETUP:
   - Create a new project in the Supabase Dashboard.
   - Go to the **SQL Editor** and run the scripts found in `supabase/migrations/` in order (001 to 010).
   - Go to **Project Settings -> API** to get your URL and Anon Key.
   - Go to **Authentication -> Providers** and enable Google if you want OAuth support.

4. ENVIRONMENT VARIABLES:
   Create a `.env.local` file in the root directory:
   ```env
   NEXT_PUBLIC_SUPABASE_URL=your_project_url
   NEXT_PUBLIC_SUPABASE_ANON_KEY=your_anon_key
   NEXT_PUBLIC_SITE_URL=http://localhost:3000
   ```

5. RUN LOCALLY:
   ```bash
   npm run dev
   ```
   Open `http://localhost:3000` in your browser.

IN-DEPTH DATABASE SCHEMA (POSTGRESQL)
--------------------------------------
TaskFlow uses a highly relational schema optimized for speed and data integrity, protected by Supabase Row Level Security (RLS).

1. public.users
   - Primary key linked to `auth.users` via UUID.
   - Automatically synced via database triggers on signup.
   - Stores metadata like `full_name` and `avatar_url`.

2. public.projects
   - The core workspace entity.
   - Each project has an `owner_id` (the creator).
   - RLS Policy: Only visible to project members.

3. public.project_members
   - Junction table for the many-to-many relationship between Users and Projects.
   - Roles: `admin` (can manage settings/members) or `member` (can manage tasks).
   - Enforces unique membership per project/user pair.

4. public.tasks
   - Belongs to a `project_id`.
   - Fields: `status` (Enum: todo, in_progress, done), `priority` (Enum: low, medium, high), `assignee_id`.
   - RLS Policy: Members can view/insert; only Admins or the Assignee can update.

5. public.task_activity_logs
   - Immutable audit trail.
   - Uses JSONB fields (`old_value`, `new_value`) to track delta changes.
   - Automatically populated via application logic or database triggers.

6. public.notifications & complaints
   - `notifications`: User-specific alerts for assignments and status changes.
   - `complaints`: System for reporting issues within a project.

7. Database Triggers & Functions
   - `handle_new_user()`: Syncs auth profiles.
   - `handle_new_project()`: Automatically makes the creator an 'admin'.
   - `update_updated_at()`: Standard timestamp management.

DEPLOYMENT GUIDE (RAILWAY)
--------------------------
1. Link GitHub repository to Railway.app.
2. Set Environment Variables:
   - NEXT_PUBLIC_SUPABASE_URL
   - NEXT_PUBLIC_SUPABASE_ANON_KEY
   - NEXT_PUBLIC_SITE_URL (Railway URL)
3. Whitelist the Railway URL in Supabase Auth -> Redirect URLs.
4. Railway handles the build and deployment automatically.

USER ACCESS CONTROL
-------------------
- Public: Login and Signup pages.
- Authenticated Users: Dashboard, Projects, Settings.
- Project Members: View and update tasks within their projects.
- Project Admins: Full management of project settings and members.
- System Admins: Global user and project management access (Role defined in migration 008).
